# 纵向项目限项检查器

[![Rocq](https://img.shields.io/badge/formalized%20in-Rocq-6b4fbb)](https://rocq-prover.org/)
[![Deploy GitHub Pages](https://github.com/zhezhouzz/grant-limit-checker/actions/workflows/pages.yml/badge.svg)](https://github.com/zhezhouzz/grant-limit-checker/actions/workflows/pages.yml)

一个开源的纵向科研项目限项检查器，适用于国家自然科学基金委、科技部等主管部门的项目申报。

项目把限项规定写成 Rocq 中的形式化定义和判定函数，再抽取为 OCaml，由网页计算器直接运行。使用者从下拉菜单中选择项目类型、角色和状态，并填写年份、金额等信息。每条检查结果都附有对应的正式文件、适用年度和具体条款。

> **免责声明：** 本项目是非官方的开源工具，与国家自然科学基金委员会、科学技术部等主管部门没有隶属关系。检查结果仅供申报准备参考，请以申报当年的正式指南和主管部门解释为准。

## 当前状态

项目目前处于早期阶段，包括 2026 年国家自然科学基金的部分通用规则、跨部门联合限项，以及两批国家重点研发计划专项指南中的限项规则：

- 同一申请人同年只能申请 1 项同类型项目（仅实现一般情形）；
- 高级职称人员，纳入总数范围的申请和在研项目合计限 2 项；
- 非高级职称人员，作为申请人申请与负责人在研合计限 1 项；
- 非高级职称人员，作为主要参与者申请与在研合计限 2 项；
- 检查时分别填写申请年度、项目批准或开始年度，以及精确到日的执行期结束时间（含延期）；基金委的“申请当年资助期满”和科技部的“早于2026年12月31日”分别按各自规则判断；
- 高级/非高级职称主要参与者的 2020/2023 年计数起点，以及晋升高级职称后的参与项目例外；
- 批准年份、完整结束日期、基金委直接费用和科技部中央财政专项资金预算分别填写，再由形式化规则判断相应的时间和金额条件；
- 国科办资〔2022〕107 号规定的跨部门联合限项：符合实施范围的申请和在研项目合计限 2 项；
- 国家重点研发计划、国家科技重大专项，以及青年科学家、科技型中小企业、国际合作类和部门推荐等项目标识；
- 青年科学家项目等文件明确列出的项目不进入相应联合限项计数。
- 国家重点研发计划、国家科技重大专项的在研项目负责人，不得再牵头或以参与者身份申报新的项目（课题）。
- 作为项目或课题负责人，同期牵头申报国家重点研发计划、国家科技重大专项合计限1项；
- 按所选2026专项指南分别检查课题负责人再次牵头、项目骨干/其他研究人员以及申报和在研合计2项规则；
- 区分不超过400万元的政府间/战略性国际合作预算例外，以及退出团队后在原执行期内的限制；
- 如果还需要结合具体专项规定判断，检查器会列出需要继续核对的内容。

科技部部分目前包括“发育编程及其代谢调节/合成生物学”两个专项，以及2026年11月发布的数学、物理、催化、人工智能等五个专项。其他重点专项请选择并核对各自的申报指南。

## 架构

```text
formal/              Rocq 模型、2026 规则、检查器和证明
      │ extraction
      ▼
kernel/generated/    Rocq 抽取的 OCaml
kernel/               OCaml → JavaScript 边界（js_of_ocaml）
      │ kernel.js
      ▼
web/                  Vite + TypeScript 静态网页
docs/sources/         来源目录与规则—条款映射
```

所有限项判断都由抽取后的 OCaml 内核完成。TypeScript 负责整理输入、调用内核，并把规则编号展示成容易阅读的检查结果。Rocq 中的领域定义和注释使用中文；`Extraction.v` 保留了一层 ASCII 包装器，供 OCaml 接口调用。

网页的“形式化模型”视图在构建时直接导入 `formal/Model.v`、`Rules2026.v`、`Checker.v` 和 `Soundness.v`，因此展示内容与当前部署版本保持同步。

## 本地运行

依赖：Rocq、OCaml、Dune、js_of_ocaml、Node.js 20+。

```sh
opam install . --deps-only
npm --prefix web install
make verify
make dev
```

然后打开 Vite 输出的本地地址。生产构建：

```sh
make build
```

静态文件位于 `web/dist/`，可直接部署到 GitHub Pages。
OCaml 网页内核使用 Dune `release` profile 构建。验证流程还会检查内核体积，确保发布的是精简的 release 构建。

## 添加规则

1. 先在 `docs/sources/` 登记官方来源、归档链接、页码/条款及原文摘要。
2. 在 Rocq 中添加带稳定 ID 的规则，并把复杂条件拆成可审查的定义。
3. 为允许、拒绝、边界年份和例外情形添加证明或测试。
4. 抽取 OCaml 内核，更新网页诊断文案。
5. 在 Issue 或 Pull Request 中说明规则解释；如规则存在歧义，应在检查结果中明确列出需要继续核对的内容。
